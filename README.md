# 一个自己用的闹钟app

## Android 工程（Kotlin + Jetpack Compose）

本目录已包含可直接用 **Android Studio** 打开构建的 Gradle 工程，应用 ID：`com.nierduolong.morningbell`，产品名：**你尔多龙吗**。

### 如何构建 / 安装到小米手机

1. 安装 [Android Studio](https://developer.android.com/studio)，首次打开会自动拉取 Android SDK。
2. 用 Android Studio **Open** 本文件夹根目录（含 `settings.gradle.kts`）。
3. **一键打包发 APK**：在项目根目录执行 `./package_apk.sh`，会在 `dist/你尔多龙吗.apk` 生成安装包（默认先 `clean` 再构建，避免 KSP 偶发失败；要快可加 `./package_apk.sh --fast`）。
4. 若手动命令行构建：执行 `./gradlew :app:assembleDebug`，APK 位于  
   `app/build/outputs/apk/debug/app-debug.apk`，拷到手机安装即可（侧载）。  
   Room 已通过 KSP **生成 Kotlin**（`room.generateKotlin`），避免旧版 Java 生成物在增量构建里叠加导致 **`AppDatabase_Impl` 类重复**；若仍异常请先 `./gradlew clean`。
5. **首次在本机命令行构建**需要 `local.properties` 中的 `sdk.dir` 指向你的 SDK（仓库里有一份示例路径；若与你的电脑不一致请自行修改）。
6. **小米 HyperOS**：请在系统设置里为该应用开启 **自启动、后台无限制、精确闹钟** 等，否则可能被推迟或杀后台。
7. **日志拍摄提醒**：在「日志」页右上角铃铛里选择每小时 / 每 3 小时 / 随机 / 关闭，并设置「只在这段时间提醒」的活跃时段（默认 9:00–22:00）。提醒用 `AlarmManager` 精确闹钟自续期触发通知，点击通知直达拍摄页；开机后会自动补排。同样建议开启自启动、精确闹钟等系统权限以保证提醒不被系统杀掉。

### 功能定位

App 分三大 Tab：**日志**（默认启动页，仿 Setlog 的每日短视频记录 + 自动合成）、**闹钟**（原有定时闹钟 + 连锁闹钟）、**我的**（昵称、语录主题包、快捷入口）。已移除原「每日视频打卡」与「早起统计」两项功能，小芽 Companion 改为仅基于心情记录驱动成长。

视觉上统一为简约社交风：白底（深色模式纯黑）、近黑文字、发丝级描边，颜色只在强调处保留一点薄荷绿；内容区以视频缩略图网格为主体。

房主页面会显示包含热点凭据、房间 ID 与邀请码的二维码；成员可在 App 内直接扫码，也可由系统扫码入口唤起 App。扫码并不会绕过鉴权：App 会在当前 Wi-Fi 中发现真实主机、核对房间 ID，再做设备签名握手。首次加入后，App 在前台用 12 秒轻量心跳保持连接，断线按 3–30 秒退避自动恢复，每 24 秒同步当天小型元数据；切后台即停止发现和心跳。连接页会明确区分权限、热点未连接、发现失败、邀请码错误和房主无响应，并展示谁在线、谁今天已经记录。

多人合成前会并发发送最多 4 路 `HEAD` 小请求检查原片是否在线，不下载视频。若有成员离线，用户可以等待并重新检查，或明确跳过不可用素材生成临时版本；原记录不会被删除，成员上线后仍可重新生成完整版。合成期间再次掉线时会显示可执行的故障原因，并保留旧成片。

### 附近快传与相机卡

手机分享端会显示两个模式：「创建无流量热点」由 App 申请 LocalOnlyHotspot；「当前热点 / Wi-Fi」可复用已经运行的附近 Log 热点、手动个人热点或路由器。接收端无需安装 App，连入同一网络后打开带临时令牌的地址即可。令牌不会进入 NSD 广播，停止分享后立即失效。

相机卡和 U 盘始终通过系统 SAF 目录授权只读访问，不猜测 `/storage/UUID`，也不把原片复制到手机。Android 11+ 可能禁止授权存储根目录；遇到“不能使用此文件夹”时，进入卡内 `DCIM` 或具体相机目录再授权即可。拔盘广播只作为提示，App 会再次探测真实授权目录，确认不可读才停止，避免拔掉键盘等无关 USB 设备时误停。浏览目录按层读取；相机卡最多两路并发原片读取、缩略图单路生成，减少慢卡随机寻址和读卡器发热。传完应先在 App 停止分享，再从系统弹出存储并拔卡。

大文件或整卡下载推荐使用 [`tools/nearby-transfer/download.py`](tools/nearby-transfer/download.py)：它用 `.part`、ETag 和 If-Range 自动续传，并逐目录枚举，避免手机一次扫描整张卡。浏览器 ZIP 只适合少量临时文件，不支持断点续传。

### 稳定性与存储

- 崩溃栈落盘在 `files/crash/`，「我的」页出现崩溃记录时可分享导出（无服务端也能排查）。
- 视频存 app 私有目录（免存储权限），按日归档；缩略图两级缓存并有 40MB 上限；启动时清理崩溃残留的孤儿文件（按文件名比对 + 多重保险，不会误删在册素材）。
- 附近 Log 的视频中继统一使用 64KiB 缓冲；8 路并发的应用层传输缓冲约 512KiB。合成只保留最终产物，输入从拍摄手机直接流入 Media3，因此不需要“全部成员原片 + 合成临时片”的额外峰值空间。
- 附近快传原片使用 128KiB 固定缓冲，服务端总连接与单客户端连接都有限流；图片预览先按像素预算下采样、校正相机 EXIF 方向，再写入最多 64MiB 的磁盘缓存，不在内存中保留整份编码 JPEG。ZIP 直接写 socket，不生成临时压缩包。
- 缩略图内存 LRU 按实际 ARGB 字节限制为 16MiB（不再按“80 张”计数），最多 2 路并发解码；解码远端 JPEG 前先读尺寸并下采样。App 进后台或系统内存紧张时会主动缩减/清空该缓存。
- ExoPlayer 前向缓冲上限收紧为 15 秒，不保留 back buffer；退出播放页即释放 Player 和进程内播放队列。
- 「我的」页按本机原片、每日合成、可重建缩略图、临时/其他文件分类显示占用和剩余空间；“安全清理”只删除缩略图、过期临时文件与通过孤儿保险规则的残留，不触碰在册原片或合成。
- 数据库里存**相对路径**（`dailylog/` 起算），读取时才解析成绝对路径：换机、恢复备份、分区变化都不会让历史记录集体变成死链；首次升级会自动把旧的绝对路径归一化，找不到的文件按文件名重定位。
- 启动自愈有固定顺序：路径归一化 → 清孤儿文件 → 补合成昨天 → 套用保留策略。保留策略永远排在合成之后，保证不会清掉还没合成的日期。
- 云备份排除视频本体、保留数据库与设置（`res/xml/backup_rules.xml`），避免超出备份体积上限导致整体备份失败。
- Release 包不再允许数据库「推平重建」，缺失迁移会直接暴露而不是静默清库。
